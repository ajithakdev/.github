# Contributing

Thanks for wanting to help. First-time contributors and students are welcome, and you don't need to ask permission to start.

## Finding something to work on

Look for issues labelled `good first issue` or `help wanted`. Comment on the issue to say you're taking it so two people don't do the same work. If you have your own idea, open an issue first so we can agree on it before you write code.

## Making a change

1. Fork the repo and create a branch from `main`.
2. Follow the setup steps in the repo's README and check that it runs before you change anything.
3. Keep the pull request to one change. Small PRs get reviewed faster.
4. Run the project's tests or build if it has them, and say in the PR how you checked your change.
5. Open the pull request and link the issue it fixes, for example `Fixes #12`.

I review every pull request, usually within a few days. If I ask for changes, push them to the same branch.

## Things that get a PR closed

- Changes that only reword text or reformat code with no real fix.
- Generated code you haven't run or can't explain.
- Several unrelated changes in one PR.

## Questions

Ask in the repo's Discussions if it has them, otherwise in the issue, or email hello@ajithakdev.com.
